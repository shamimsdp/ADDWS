# Change requests

Owner: Nadia (CR manager). Minhaj classifies every client requirement change first; only CRs are recorded in the register. Process: `.claude/agents/nadia-cr-manager.md`. One file per CR in `change-requests/` (template: `change-requests/_template.md`).

## Classification (Minhaj)

| Type | Examples | Handling |
|---|---|---|
| Minor — not a CR | Text/label/copy change, color change, small font or spacing change with no behavior, data, flow or estimate impact | Minhaj logs it below and runs it as Fast-lane work |
| CR | New feature or function; addition to or change of an existing feature/function; any change to data, workflows, permissions, integrations, acceptance criteria, effort or schedule | Minhaj flags it to Nadia; nothing is built until the client approves |

When unsure, treat it as a CR.

## Status legend

| Status | Meaning |
|---|---|
| `Raised` | Minhaj flagged it; Nadia registered it |
| `Impact assessed` | Scope, effort and schedule impact recorded |
| `Client notified` | User confirmed the client notification was sent |
| `Approved` / `Deferred` / `Rejected` | Client decision recorded |
| `Scheduled` | Approved scope added to `feature-list.md` and `feature-progress-list.md` |
